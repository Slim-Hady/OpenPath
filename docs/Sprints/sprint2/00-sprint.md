## 1. Description

This sprint delivers the product's core value: turning a completed developer profile into three ranked GitHub issues with a reason for each. It covers the full selection pipeline — profile-based discovery, filters, exclusion of unsuitable issues, AI ranking, details, regeneration, confirm/ignore, and selecting from saved items. It also starts enforcing the Admin's AI settings on every AI request.

This is the sprint that must prove the business goal: a developer can find a suitable contribution without searching manually.

## 3. User stories and acceptance criteria

### FR-4 Manage Issue Discovery

**US-4.1 · Search for issues from my profile — 8 points**

_As a developer, I need to request an issue search based on my profile, so that I find open Issues without searching manually._

- [ ] Given my profile is complete, when I request a search, then open Issues matching my languages, technologies and level are retrieved from GitHub.

**US-4.2 · Filter the search — 3 points**

_As a developer, I need to filter by language, label, repository activity, organization or repository, so that I can narrow the results._

- [ ] Given I apply a language or "good first issue" label filter, when I search, then only matching Issues are returned.
- [ ] Given I restrict the search to an organization or repository, when I search, then Issues come only from it.

**US-4.3 · Exclude unsuitable issues — 5 points**

_As a developer, I need closed, assigned, inactive, selected or ignored Issues removed, so that I only see Issues I can work on._

- [ ] Given the search finds closed, assigned or inactive Issues, when the pool is built, then they are excluded.
- [ ] Given I already selected or ignored an Issue, when I search, then it does not appear.
- [ ] Given candidates remain, when the pool is built, then repository context is attached and the pool is passed to matching.

**US-4.4 · Handle empty results — 1 point**

_As a developer, I need to be told when no suitable Issues are found, so that I can broaden my filters._

- [ ] Given no Issues match, when the search ends, then I see a "no suitable issues" message with an offer to broaden the filters.

### FR-5 Manage Issue Matching

**US-5.1 · Get the top three recommendations — 8 points**

_As a developer, I need to receive the three Issues that best match my profile, so that I can pick a suitable contribution._

- [ ] Given a candidate pool exists, when matching runs, then the AI ranks it and I receive the three highest-ranked Issues.
- [ ] Given recommendations are requested, when they are ready, then they are displayed within 10 seconds for most requests.

**US-5.2 · View issue details and reason — 3 points**

_As a developer, I need to see each recommended Issue's repository details, requirements and why it was recommended, so that I can judge the fit._

- [ ] Given I see recommendations, when I open one, then I see the repository name, description, link, required technologies, level and prerequisites.
- [ ] Given I view a recommendation, when it loads, then I see a short explanation of why it fits me.

**US-5.3 · Regenerate recommendations — 3 points**

_As a developer, I need to regenerate the recommendations, so that I can see three different Issues._

- [ ] Given I have three recommendations, when I press regenerate, then I receive three Issues different from the previous ones.
- [ ] Given I regenerate, when it completes, then the suggestion and regeneration are recorded for the Admin Dashboard.

### FR-6 Manage Issue Selection

**US-6.1 · View details and select an issue — 2 points**

_As a developer, I need to view the full details of an Issue before selecting it, so that I choose with confidence._

- [ ] Given I see recommended Issues, when I open one, then I see its complete details.
- [ ] Given I decide to work on it, when I choose select, then I am asked to confirm.

**US-6.2 · Confirm selection — 2 points**

_As a developer, I need to confirm my selected Issue, so that it is tracked on my account._

- [ ] Given I pressed select, when I confirm, then the Issue is associated with my account with status In Progress.
- [ ] Given I do not confirm, when I cancel, then no selection is made.

**US-6.3 · Ignore an issue — 2 points**

_As a developer, I need to ignore an Issue I do not want, so that it is not recommended again._

- [ ] Given I ignore an Issue, when I request new recommendations, then that Issue never appears again.

**US-6.4 · Select from saved items — 1 point**

_As a developer, I need to select an Issue from my saved items, so that I can start one I bookmarked earlier._

- [ ] Given I have saved Issues, when I choose one and confirm, then it becomes my selected Issue.

### FR-7 Manage Saved Items (partial)

**US-7.1 · Bookmark and organize — 3 points**

_As a developer, I need to bookmark repositories and Issues in named lists and move or remove them, so that I keep what interests me._

- [ ] Given I view a repository or Issue, when I bookmark it, then it appears in my saved items.
- [ ] Given I create a named list, when I move or remove items, then the changes are saved.
- [ ] Given another user, when they try to open my lists, then access is denied.

### FR-20 Manage AI Settings (partial)

**US-20.3 · Enforce AI settings — 5 points**

_As an Admin, I need the settings applied to every AI feature starting from the next request, so that the budget is protected._

- [ ] Given I changed the settings, when the next AI request is made, then the new values apply to CV extraction, matching, onboarding and the AI guide.
- [ ] Given the usage limit is reached, when a user makes an AI request, then it is blocked and the user is informed.

## 4. Technical work

### Data model

- `github_issues` cache with repository context, labels, state, assignee and last activity.
- `recommendations` (user, issue, rank, reason, created_at, regenerated_from).
- `suggestion_events` for suggestions and regenerations (feeds FR-19).
- `selections` (user, issue, status `In Progress`, selected_at) and `ignored_issues`.
- `saved_lists` and `saved_items` with ownership constraints.
- `ai_usage` per user/feature/request (tokens, model, timestamp).
- Indexes for issue search by language, label, repository, organization and state.

### API and integrations

Endpoints and manual checks live in [`01-api.md`](01-api.md).

- Endpoints for search, filters, recommendations, regenerate, issue details, select, confirm, ignore and saved lists; document in `../API.md`.
- GitHub discovery: search open issues with pagination, rate-limit handling and caching; fetch repository context for candidates.
- AI matching: build a compact candidate payload, request structured JSON (issue id, rank, reason), validate output, reject unknown IDs, fall back to deterministic ranking if AI fails or times out.
- Enforce exactly three unique recommendations; never include ignored, selected, closed, assigned or inactive issues.
- Regenerate excludes the previous set and records a suggestion event.
- AI enforcement middleware reads `ai_settings` on every request, applies tokens/temperature, meters usage and blocks at the limit.
- Ownership checks for saved lists and selections.

### UI screens

- Search form with filters (language, label, activity, organization, repository).
- Recommendation cards with rank, repository, level and reason.
- Issue details with select/ignore/save actions and confirmation dialog.
- Saved items with lists, move/remove and "select this issue".
- Empty state with "broaden filters" action.
- Loading, timeout and AI-error states.

- API endpoints documented in `../API.md`.
